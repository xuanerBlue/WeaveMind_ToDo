# WeaveMind 待办 —— 改造计划

> 依据 [需求.md](需求.md) 对现有实现做的差距分析与分阶段改造方案。
> 本文档写于开工前，用于确认范围；开工后若有偏离，在此处记录原因。

## 一、现状盘点

技术栈：Tauri v2 + 原生 TypeScript（无框架）+ Vite 多入口。
两个独立窗口各自加载自己的 bundle，靠 Tauri event 通信。

| 模块 | 文件 | 现状 |
|---|---|---|
| 窗口 / 托盘 / 自启 | `src-tauri/src/lib.rs` | 完整可用，**基本不用动** |
| 文件读写 / 配置 / 监听 | `src-tauri/src/lib.rs` + `src/bridge.ts` | 完整可用，**基本不用动** |
| 悬浮球 | `src/ball.ts` | 拖动、置顶、角标已有，**计数口径要改** |
| 数据模型 | `src/types.ts` | **要重构** |
| md 解析与读写 | `src/todo-parser.ts` | **改动最大** |
| 面板 UI | `panel.html` / `src/panel.ts` / `src/styles/panel.css` | **基本重做** |

### 已经满足需求的部分

- 球始终置顶、可随意拖动、位置持久化。
- 球上显示未完成数量角标。
- 点球开关面板、点面板外收回面板。
- 外部改动 md 后自动重载（含"忽略自己写入引发的回声"这一层）。
- md 读写只改任务行，其余内容逐字节保留。
- 优先级 emoji、`📅` 截止、`✅` 完成日期的解析与写回。

### 与需求不符 / 缺失的部分

**数据模型**
- 优先级是 Obsidian Tasks 全套六档（含 `🔽` `⏬`），需求只要四档。
- 状态只有 `checked: boolean` 两态，缺"已放弃"。
- 缺 `➕` 创建日期、`❌` 放弃日期。
- 缺"类别"概念；现有的 `tags`（`#标签`）是另一套东西，需求已否掉。

**解析器**
- 不解析 frontmatter，无 `categories` 清单。
- 不识别 `## 标题` 分区，任务没有归属。
- `TASK_RE` 不认 `- [-]`（放弃态的行目前会被整行忽略）。
- `add()` 一律追加到文件末尾，不会按类别落到对应分区。
- 没有"完成/放弃后把行沉到分区下半部"的移行逻辑。
- 有 `remove()`（真删除），需求明确不做删除。
- `sortTodos()` 只有一种固定排序，没有精选算法，没有多排序策略。

**面板 UI**
- 没有侧边标签条，没有视图概念（精选 / 超期 / 归档 / 类别）。
- 没有精选算法。
- 录入是"行内语法 + 回车"，需求要的是**表单弹窗**。
- 编辑是"点正文原地改 + 优先级角标轮换 + 日期 input"，需求要的是**同一个表单弹窗**。
- 条目右侧是删除按钮，需求要的是**放弃**。
- 没有排序角标。
- 没有设置界面（类别的新增 / 改名 / 删除）。
- 面板宽 376px，没有给标签条留位置。

**其他**
- 缺 Esc 关闭面板。
- 外部重载时的策略是"正在编辑就跳过重载"，需求要的是"重载列表数据、但不影响已打开的表单"。
- `Todo.example.md` 是旧格式，README / DEVELOPMENT.md 需同步。

## 二、已定结论

开工前确认的三个判断，外加一条界面口径。

### 1. 解析器保留行模型

只改任务行，用户在 md 里手写的段落、标题、空行逐字节保留。
代价是分区边界与行移动的处理更绕，但这个文件躺在 Obsidian vault 里，
抹掉手写内容不可接受，且现有实现已经稳定，重写不划算。

做法：给 `TodoDoc` 增加一层"分区索引"——解析时记录每个 `##` 标题的行号区间，
任务归属于其上方最近的类别标题；写回仍是行级操作，移行用 splice + reparse。

### 2. 无创建日期的老条目：读取时不写文件

无 `➕` 的条目，其有效到期视为无限远，排在同档最后；
该条目**首次被操作**（勾选 / 编辑 / 改优先级 / 放弃）时才补写 `➕` 为当天。

副作用：在补写之前，这些条目参与不了精选第 6 条配额位的"躺得最久"比较，会被跳过。
不采用"首次打开就全文补写"的做法——那等于篡改历史，且会让老条目三天后集体超期。

### 3. 非类别标题原样保留

只有 frontmatter `categories` 里列出的标题才算类别分区。
其余标题（如 `## 备注`）原样保留，其下的任务归"默认"类别参与展示，
但**不参与行移动**——完成沉底只在真正的类别分区内做，以免打乱用户自己的排版。

### 4. 界面不显示 emoji，一律文字色块

md 里继续用 emoji 存储（Obsidian 兼容的前提），界面渲染时全部翻译成文字 + 背景色块，
具体见需求文档第六节「视觉标识」。

读到 `🔽` `⏬` 这两个需求里没有的档位时：解析保留原 emoji 不篡改，排序并入"一般"档，
界面显示为灰底「低」，表单不提供这两个选项。

## 三、分阶段改造

四个阶段，每个阶段结束时应用都能跑、能验证。

### 阶段 1：数据模型与解析器（无 UI 变化）✅ 已完成

`src/types.ts`
- `Priority` 收窄为四档：`highest` / `high` / `medium` / `none`（保留 `low`/`lowest` 仅用于解析兼容）。
- `Todo` 改为：`status: "open" | "done" | "cancelled"`，新增 `created` / `cancelled` 日期、`category`。
- 新增 `Category` 与 `TodoDocMeta`（frontmatter 里的 categories 清单）。

`src/todo-parser.ts`
- 解析 / 写回 frontmatter 的 `categories`。
- 识别 `##` 分区，建立"标题 → 行号区间"索引，为每条任务标记 `category`。
- `TASK_RE` 支持 `- [-]`；抽取 `➕` 与 `❌` 日期并按规范写回。
- `add(text, category)`：插入到目标分区**未完成区的末尾**（分区不存在时先创建标题）。
- `complete()` / `cancel()` / `reopen()`：改状态、写 / 清日期、把行沉到分区下半部。
- 删掉 `remove()`。
- 排序拆成：`sortBy(策略)` + `pickFeatured()`（精选算法，含第 6 条配额位）。

**验收**：写一组针对解析器的手工用例，覆盖三态往返、分区归属、
沉底后行序、frontmatter 增删类别、无 `➕` 的老条目。UI 此时仍是旧的。

### 阶段 2 + 3：面板重做（两阶段合并）✅ 已完成

> **偏离记录**：原计划把"视图与色块"和"表单与条目交互"分成两阶段，实际合并执行。
> 原因是条目的渲染（色块）与交互（点开表单、勾选、放弃）落在同一段 `renderItem` 代码里，
> 分两次改等于写两遍。交付内容没有变化。

#### 原阶段 2：面板骨架与视图

`panel.html` / `panel.css`
- 布局改成：左侧竖排文本标签条（上区视图 / 下区类别）+ 间隙 + 右侧圆角卡片。
- 窗口宽度从 376 加到约 460（标签条 + 间隙），`tauri.conf.json` 同步。

`src/panel.ts`
- 引入视图状态：`featured | overdue | archive | category:<名字>`。
- 四种视图的取数与渲染。
- 排序角标（优先级 / 创建时间 / 截止时间 / 已超期时长；归档视图换成结束时间），
  精选视图不显示角标。
- 超期视图默认按已超期时长降序，归档默认按结束日期倒序。
- 条目渲染改为**文字色块**：优先级、日期、类别三类色块，含预设色板与"类别名 → 颜色"的派生函数。

**验收**：能在各视图间切换，精选六条的选取符合算法（含配额位边界），
超期只收手填过截止日的条目。

#### 原阶段 3：表单与条目交互

- 新建 / 编辑共用一个弹窗：标题、优先级、截止日期、类别。
  新建时类别默认等于当前所在的类别视图，系统视图下默认为"默认"类。
  表单里的优先级选择器沿用同一套色块样式，不出现 emoji。
- 条目交互改为：勾选框 = 完成；悬停 `×` = 放弃（无确认）；点条目 = 打开表单。
- 移除：行内语法输入框、内联编辑、优先级轮换角标、日期 input。

**验收**：三态流转正确写回 md；放弃的条目从当前视图消失、出现在归档里。

### 阶段 4：设置、收尾与文档 ✅ 已完成

- 设置界面：类别新增 / 改名（同时改 frontmatter 与分区标题）/ 删除（任务移到"默认"）。
- 类别名 ≤ 4 字校验。
- Esc 关闭面板。
- 球角标计数口径改为"排除已完成与已放弃"。
- 外部重载改为"只覆盖列表数据"，表单打开时不被冲掉；表单提交时处理"目标条目已被外部删掉"。
- 更新 `Todo.example.md` 为新格式；同步 README 与 DEVELOPMENT.md。

**已在 dev-preview 里实测通过**：四类视图取数与默认排序、精选算法（含第 6 条配额位真的把
按序补位的那条挤掉了）、超期只认手填截止日、类别色块只在跨类别视图出现、表单新建与编辑、
完成与放弃的沉底与留痕、类别改名（frontmatter 与分区标题同步）、类别删除（两步确认、

`weave-id`、`## 备注` 下的自由文字、未被操作的条目全部零改动。

**尚未在真实 Tauri 环境验证**：悬浮球拖动与置顶、面板贴球定位与 `data-side` 镜像、
失焦收回、托盘、文件监听，以及原生 `date` 控件在 macOS WKWebView 里的表现。
这些要 `npm run tauri:dev`。

## 五、风险

1. **改名类别涉及两处**（frontmatter 清单 + 分区标题），任一处漏改都会让整个分区的任务
   落到一个不存在的类别上。这一操作要有明确的原子写回路径。
2. **行移动与 lineIndex 失效**。现有模型按 `lineIndex` 定位，沉底会移动行；
   每次移行后必须立即 reparse，UI 侧持有的旧 lineIndex 也要一并失效重取。
3. **外部重载与表单并存**。现有做法是编辑期间跳过重载，改成并存后，
   要处理"表单提交时目标条目已不在"的竞态。
4. **面板变宽后的贴边定位**。现有逻辑按球的位置左右择向摆放，
   宽度变化后靠近屏幕边缘的表现要重测。

## 六、开发预览页

`dev-preview.html` 是给面板 UI 用的浏览器预览页：注入一份最小的 Tauri mock
（`invoke` / 事件 / 窗口 API）和一份样例 md，然后原样加载 `src/panel.ts`，
因此**不启动 Tauri、不编译 Rust** 就能验证视图切换、精选算法、表单、色块和写回结果，
右侧黑色面板会打印每次写回的完整 md。

跑法：`npm run dev` 后访问 <http://localhost:1420/dev-preview.html>。
它不在 `vite.config.ts` 的打包入口里，不会进产物。

它验证不了的部分只有真正依赖 Tauri 的那一层：悬浮球拖动与置顶、面板贴球定位与
`data-side` 镜像、失焦收回、托盘、文件监听——这些要 `npm run tauri:dev` 看。
