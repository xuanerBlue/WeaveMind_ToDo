# WeaveMind 待办 —— 需求定稿

> 本文档是 2026-09-09 一轮需求讨论的产物。记录的是**决策及其理由**，
> 不是实现说明。凡是被否掉的选项都留在"明确不做"一节，避免后续反复。

## 一、定位

一个常驻悬浮球 + 展开面板的个人待办工具。**md 文件是唯一事实源**，
软件每次启动从 md 全量重建，不在 md 之外保存任何状态。

对抗清单膨胀靠三条机制：

1. 完成即从视图消失（md 留痕）
2. 默认只呈现最该干的六条
3. 提供"我不做了"作为排水口

> 为什么需要第 3 条：只有"完成"的话，清单只有进没有出——真正该清掉的那批
> 条目你根本不打算完成，只是不想做了。没有排水口，球上的数字只会单调上涨。

## 二、一条待办的字段

| 字段 | 说明 |
|---|---|
| 标题 | 必填 |
| 状态 | 未做 / 已完成 / 已放弃（三态） |
| 优先级 | 四档：重要且紧急 > 紧急 > 重要 > 一般（默认一般） |
| 创建日期 | 软件自动写 |
| 截止日期 | **选填**。填了才有"超期"资格 |
| 结束日期 | 完成或放弃时自动写 |
| 类别 | 必属且只属一个 |

## 三、类别

- 平铺互斥，**无层级、无多标签**，一条待办只属一个类别。
- 内置一个"默认"类别。可在设置里新增 / 改名 / 删除。
- 名称 ≤ 4 字（受竖排文本标签条的宽度约束）。
- 类别清单存在 md 的 frontmatter 里，因此**空类别不会丢**；其顺序即标签条顺序。

**删除类别**：底下的任务全部移到"默认"类别，不销毁。
删类别是整理动作，不该顺手把任务一起干掉。

**改名类别**：只改名称，**任务归属不动**。
实现上要同时改两处——frontmatter 里的清单，以及 md 里对应的分区标题。
新名称同样受 ≤ 4 字约束。

## 四、视图

| 视图 | 内容 |
|---|---|
| 精选 | 全局算法选出的六条，见第五节 |
| 超期 | 跨类别，收所有「填了截止日 且 已过期 且 未完成」的条目 |
| 归档 | 跨类别，收所有已完成和已放弃 |
| 各类别视图 | 该类别下的全部**未完成**条目 |

- **已完成的条目一律只在归档里看**，不出现在任何其他视图。
- 排序角标只出现在超期、归档、类别视图上，**精选没有排序开关**——排序就是精选的定义，
  一旦可改，第六条的配额规则就不成立了。
- 角标选项：优先级 / 创建时间 / 截止时间 / 已超期时长。归档视图里换成结束时间。
- 超期视图默认按**已超期时长降序**（超得最久的在最上）。
- 归档视图默认按**结束日期倒序**（最近干完的在最上）——打开归档多半是想看最近干了啥，
  不是考古。

## 五、精选算法

1. 候选集 = 全部未完成条目，**不分类别**。
2. 定义**有效到期** = 手填的截止日期；没填则取 `创建日期 + 3 天`。
   这个值**只用于排序，绝不用于判定超期**，也不写进 md。
3. 排序：优先级四档降序 → 同档内按有效到期升序。取**前 5 条**。
4. **第 6 条是配额位**，留给"重要"档（即重要不紧急）中创建时间最早的一条。
   - 若该条已在前 5 中，取该档次早的一条；
   - 若该档为空、或该档条目已全部落在前 5 内，则第 6 条退回按序正常补位，不留空。
5. 未完成总数不足 6 条时全部显示。

> 为什么要第 4 条这个配额：优先级是手填且**不会自动上浮**，而"重要但不紧急"的事
> （学习、重构、写文档、体检）的共同特征是——它们不会自己变紧急，直到出事那天。
> 没有配额位，这一档会永久沉底，一条都进不了视野。

> 为什么"有效到期"不能用于判定超期：悬浮球鼓励随手塞，若不填截止就在三天后
> 无条件变超期，三个月后超期列表里九成是"有空看看某个库"这类东西。
> 当九成的条目都是红的，红色就不再是信号——和固件里断言满天飞最后没人看 log 一样。
> 拆开之后，超期资格只由你亲手填的日期赋予，它才重新是个强信号。

## 六、界面

**球（闭合态）**
- 显示未完成总数。不含已完成、已放弃，不区分类别，**不随侧栏选中而变**。
- 始终置顶，可随意拖动位置。

**面板（展开态）**
- 单击球展开。
- 左缘一条**竖排文本标签条**，方块内直接写文字（不用图标）：
  上区是视图（精选 / 超期 / 归档），下区是类别（含"默认"）。
- 右侧列表主区，带排序角标和新建按钮。
- 关闭方式三种都要支持：再点球 / 点击面板外部 / Esc。

**条目交互**
- 勾选框 = 完成。
- 悬停时右侧出现 `×` = 放弃，**点击即生效，不弹确认**。
  排水口不能有摩擦，加了确认弹窗它就会堵。
- 点条目本身 = 打开表单编辑。

**视觉标识（界面不出现 emoji）**
- md 里继续用 emoji 存储，那是编码层，也是 Obsidian 能识别本文件的前提；
  界面渲染时一律翻译成**文字 + 背景色块**。
- 优先级：红底「重要且紧急」/ 橙底「紧急」/ 蓝底「重要」/ 一般**不显示色块**
  （与 md 里"一般不写标记"一致，行才干净）。
- 兼容档：md 里读到 `🔽` `⏬` 时显示灰底「低」，只读；一旦在表单里改过优先级，
  就会被换成四档之一。
- 日期：已超期显示红底「超期 N 天」；未到期显示中性底「N 月 N 日截止」；
  没填截止则不显示。归档视图里显示「N 月 N 日完成」/「N 月 N 日放弃」。
- 类别：精选 / 超期 / 归档是**跨类别**视图，每条需显示所属类别的色块，
  否则分不清哪条属于谁；类别视图里不显示。颜色由类别名自动派生自一组预设色板，
  新建类别时不需要挑颜色。
- 文案统一用「超期」，与侧边栏标签名一致，不混用「逾期」。

**新建 / 编辑表单**
- 同一个弹窗，字段：标题、优先级、截止日期、类别。
- 新建时类别默认等于当前所在的类别视图；在精选 / 超期 / 归档里新建则归"默认"类。
- 已知代价（本轮决定先不处理）：表单让录入从一步变三步，
  在"忙到一半想起一件事"的场景有漏水风险。后续若觉得别扭，
  优化方向是让表单自己能一秒完成——焦点默认落在标题输入框、
  其余字段全有默认值、敲完标题一个组合键提交。
- 实际落地：提交是 ⌘ / Ctrl + Enter，裸回车不提交只给一行提示。
  裸回车曾经直接创建，但打字打一半习惯性敲回车会把半句话提交掉。

**详情：描述与检查项**（2026-09-14 追加）

点条目打开的就是这个表单，它同时是"详情页"：除标题 / 优先级 / 截止 / 类别外，
还有**描述**（多行自由文本）和**检查项**（父任务下的子勾选清单）。

- 检查项**不是待办**。它不进任何视图、不参与精选与归档、不计入球上的数字，
  也不写完成日期。它只是父任务的一把进度刻度。
- 因此"检查项勾完 = 父任务完成"这条**不成立**，勾满了也不会自动完成、不会归档。
  完成与否始终是人的裁决——这和"优先级不自动上浮"是同一条：
  **软件不替人改人填的字段。**
- 列表上的呈现：描述只露第一行（灰色，单行省略），检查项显示 `检查项 2/5`。
  目的是让人在点进去之前就知道这条底下有东西。
- 表单里的改动（含勾选检查项）统一在点保存时落盘，取消即全部丢弃。
  这与标题、优先级的行为一致，不制造"有的字段即时生效、有的要保存"的割裂。
- 键位：描述框里回车是换行；检查项输入框里回车 = 添一项（能连着敲完一串）；
  两处的 ⌘ / Ctrl + Enter 都是保存。输入框里打了一半没回车就点保存，那一项也会被收进去。

> 为什么不做成独立的子待办：一旦子项本身是待办，它就要有优先级、截止、归属、
> 还要回答"父完成了子没完成怎么办"。而这里要的只是**把一件事拆成几步**，
> 拆完仍是**一件事**。让它只是刻度，这些问题全都不存在。

## 七、md 存储格式

```markdown
---
categories: [默认, 工作, 学习]
---

## 默认

- [ ] 想想那个方案 ➕ 2026-09-08
- [x] 装一下新固件 ➕ 2026-09-01 ✅ 2026-09-03
- [-] 研究某个库 ➕ 2026-08-20 ❌ 2026-09-05

## 工作

- [ ] 盒的关调试串口改为BLE指令方式 🔺 ➕ 2026-09-02 📅 2026-09-15
- [ ] osTimerIsRunning 有风险 ⏫ ➕ 2026-09-05
```

- **分区标题 = 类别**。每个分区内，**未完成的在上，完成和放弃的沉在下面**。
  文件会随时间变长，但结构始终清楚——从上往下读先看到还没干的。
- 状态：`- [ ]` 未做 / `- [x]` 完成 / `- [-]` 放弃。
- 优先级：`🔺` 重要且紧急 / `⏫` 紧急 / `🔼` 重要 / 一般**不写任何标记**。
  随手记的东西那一行最干净。
- 日期：`➕` 创建 / `📅` 截止（**只在手填时出现**，因此它同时就是"有超期资格"的标记）
  / `✅` 完成 / `❌` 放弃。
- 描述与检查项写成**任务行下缩进四格的子块**：普通行是描述，`- [ ]` 行是检查项。

  ```markdown
  - [ ] 对盒固件的断言做处理 ⏫ ➕ 2026-09-01
      断言满天飞之后就没人看 log 了，先把分级定下来再动代码。
      - [x] 列出现有断言的位置
      - [ ] 定分级规则
  ```

  在 Obsidian 里这就是一条任务带一段说明和一串子任务，不需要软件私有的语法。
  检查项**不写任何日期 emoji**——它没有创建、截止、完成这些字段。
  代价是解析器从"一行 = 一条待办"变成"一块 = 一条待办"，凡是移动行的地方都得整块搬。
- **不写 id，不写排序号**——没有拖拽，且每行自带全部元数据，
  软件不需要在 md 之外认人。
- 这套符号与 Obsidian Tasks 的约定一致，文件用别的 md 工具打开时标记仍可被识别。

**文末格式说明**（2026-09-14 追加）：新建待办文件时，在**文件末尾**附一段格式速查，
说明状态、优先级、日期、类别、描述与检查项分别怎么写。

- 放**底部**不放顶部：这文件是每天要扫的，顶部一段说明会把真正的待办挤下去。
- 挂在 `## 格式说明` 这个**非类别标题**下。软件因此永远不会往里插任务、也不会挪它，
  用户删掉也不影响使用——标题在不在，就是"这段说明有没有"的判据。
- 说明里的示例复选框必须包在**引用块**（行首 `>`）里，否则解析器会把它们当成真待办，
  文件一打开就多出几条幽灵条目。这条有回归用例守着。
- 已有的文件不会被自动改写；设置里给一个按钮，点一下才追加到末尾。
  **软件不主动往用户的文件里塞东西**，哪怕是说明。

**外部改动**：md 被外部程序改动时，**重新加载覆盖内存**。
实现注意：重载只应覆盖列表数据；若此时表单正打开，表单内容不受影响，
但提交时要处理"目标条目已被外部删掉"的情况。

## 八、明确不做

| 不做 | 理由 |
|---|---|
| 拖拽排序 | 顺序由字段算出，拖完下次重算就被打回，无处落脚 |
| 删除条目 | 与"md 保留全部记录"直接冲突；误建的走放弃即可 |
| 优先级随时间自动上浮 | 本轮明确否掉，改用精选第 6 条的配额位解决沉底问题 |
| 多类别 / 层级类别 | 一条只属一个类别，才能用"分区标题即类别"这种人可读的 md 结构 |
| 把默认的三天写进 md | 它只是排序用的内存推导值，写进文件会污染超期语义 |
| 已完成条目进入非归档视图 | 完成即消失，是对抗膨胀的第一条机制 |
